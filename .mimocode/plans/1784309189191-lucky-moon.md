# Convert Case Studies to Slug-Based Routes

## Goal
Convert the case study overlay into individual URL-routed pages (`/case-studies/[slug]`) for proper GA4 pageview tracking and SEO.

## Files to Create

### 1. `app/case-studies/[slug]/page.tsx` (new — server component)
- `generateStaticParams()` returns `CASE_ORDER.map(slug => ({ slug }))`
- `generateMetadata()` returns per-case title + description + OG image
- Looks up `CASES[slug]`, calls `notFound()` if missing
- Renders `<CaseStudyPage slug={slug} />`

### 2. `app/case-studies/[slug]/CaseStudyPage.tsx` (new — client component)
Adapted from `CaseStudyOverlay.tsx` with these changes:
- Props: `{ slug: string }` instead of `{ activeCase, onClose }`
- Always renders with class `case-study is-open` (no toggle)
- Back button → `router.push("/")` instead of `close()`
- Escape key → `router.push("/")`
- Related work cards → `<Link href={/case-studies/${r.slug}}>` instead of `<a>`
- Scroll progress rail uses `window` scroll (not overlay ref scroll)
- IntersectionObserver uses default root (not overlay ref)
- `useEffect` adds/removes `cs-locked` on body, scrolls to top on mount
- GA4 `page_view` event on mount via `window.gtag`
